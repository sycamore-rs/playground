# AGENTS.md

## Project overview

This repository is the online playground for **sycamore-rs**. It has a client component and a Rust server component. The server is hosted on **Azure Container Apps Express** as a Docker container.

## Repository layout

- `client/` — client-side playground code.
- `server/` — Rust/Axum service.
- `shared/` — library crate (`sycamore-playground-shared`) containing API types used by both the client and server, including `CompileRequest`.
- `compilation-env/` — Rust project and build workspace used for compiling submitted playground code to WebAssembly. It is excluded from the root Cargo workspace and not checked into git.
- `artifact-cache/precompiled/` — image-bundled examples (`request.json`, `metadata.json`, and `artifact.wasm` per registered example), generated by `--precompile`; ignored by git and preserved at startup.
- `artifact-cache/runtime/` — ephemeral WASM and metadata cache; ignored by git and cleared on server startup.
- `Dockerfile` — multi-stage image build for the server and its WebAssembly compilation environment.

## Development and verification

Run Rust commands from the repository root unless a command explicitly says otherwise:

- `cargo check --workspace` — check workspace crates.
- `cargo test --workspace` — run workspace tests.
- `cargo build --release` — build the server in release mode.
- `cargo run --package sycamore-playground-server -- --precompile` — compile all examples registered in `server/src/precompiled.rs` into `artifact-cache/precompiled/` and exit. Requires the WASM target. Run offline, not alongside a running server: both modes use the same compilation workspace.

The runtime compilation environment needs the `wasm32-unknown-unknown` Rust target. The Docker image sets this up for the container. Docker builds and container-based sample compilation checks are not required unless explicitly requested.

## Implementation notes

- Keep server changes in `server/`; its manifest is `server/Cargo.toml`.
- Define types shared by the frontend and backend in `shared/src/lib.rs`, rather than duplicating them. API request types should support both Serde serialization and deserialization, with public fields where needed by consumers.
- `POST /compile` accepts a shared `CompileRequest` and returns JSON `CompileResponse` metadata (artifact URL, original compilation duration, structured warnings, and cache-hit status). `GET /artifacts/{hash}.wasm` serves raw WebAssembly; missing artifacts return 404 and clients should resubmit the compile request. Preserve the health endpoint.
- Compilation uses the shared `compilation-env/` workspace and is serialized by a lock. Check the artifact cache before and after acquiring the lock; publish an independent artifact copy before releasing it.
- Deployment currently scales to at most one instance. Use a simple local, ephemeral artifact cache; do not add shared storage or replica-routing infrastructure for now. Request hashes include a random startup namespace; no explicit environment version is needed. Revisit artifact storage if multiple replicas are enabled.
- Cache limits are configured with `ARTIFACT_CACHE_MAX_BYTES` (default 512 MiB) and `ARTIFACT_CACHE_MAX_ENTRIES` (default 1,000). Evict least-recently-used unpinned entries, protecting artifacts for five minutes after each compile response references them. Successful compilations only are cached. The Dockerfile runs the server binary with `--precompile` during the image build. Startup registers bundled artifacts as pinned entries referencing their files directly, without compiling or copying WASM. Bundled metadata contains duration and warnings, not runtime URLs or cache-hit flags. A missing bundle is allowed in local development (lazy compilation); an incomplete or stale bundle fails startup. Size limits must leave room for the pinned example plus other artifacts, and disk needs headroom for staging and the compilation workspace.
- A full cache returns 503 with `Retry-After` rather than evicting protected artifacts. At most eight HTTP cache-miss requests may be running/queued; additional misses return 429 with `Retry-After`. Cache hits bypass this admission limit.
- Compilation is not a security sandbox: submitted Rust can read compiler environment variables and filesystem contents at compile time. Do not expose secrets to the compilation process; stronger isolation is needed before treating it as a secure untrusted-code service.
- `server/src/compiler.rs` owns compilation and diagnostic parsing for both HTTP requests (five-second timeout) and offline precompilation (five-minute timeout per example). Keep these paths aligned.
- Keep the Docker build aligned with the Rust toolchain, server dependencies, and targets needed both to run the service and compile WebAssembly. The builder stage must copy `shared/` along with the client and server workspace crates.
- Do not commit generated build output such as `target/` directories or environment-specific secrets.
